# Parsing: From Token Stream to Abstract Syntax Tree

## [1].role_in_pipeline

### Position Between Lexer and Validator

The **parser** is the semantic bridge in language processing. While the lexer identifies *what type* each lexical unit is, the parser understands *how they relate* to form meaningful structures.

```text
┌──────────────────┐
│  Lexical Analyzer│  ← "This is a KEYWORD token"
└────────┬─────────┘
         ↓ token stream
┌──────────────────┐
│     Parser       │  ← "KEYWORD + IDENTIFIER + BLOCK = function declaration"
└────────┬─────────┘
         ↓ AST
┌──────────────────┐
│  Semantic Analyzer│ ← "Is this function call valid?"
└──────────────────┘
```

### Tokens vs Abstract Syntax Tree (AST)

#### Token Stream (Lexer Output)

```text
[
    {type: "KEYWORD", value: "if", position: {line: 1, col: 1}},
    {type: "LPAREN", value: "(", position: {line: 1, col: 4}},
    {type: "IDENTIFIER", value: "x", position: {line: 1, col: 5}},
    {type: "RPAREN", value: ")", position: {line: 1, col: 6}},
    {type: "LBRACE", value: "{", position: {line: 1, col: 8}},
    ...
]
```

**Characteristics**:
- Flat list (no hierarchy)
- One-to-one with source tokens
- Classification only, no relationships

#### AST (Parser Output)

```text
{
    type: "IfStatement",
    condition: {
        type: "Identifier",
        name: "x"
    },
    consequent: {
        type: "BlockStatement",
        body: [...]
    }
}
```

**Characteristics**:
- Tree structure (hierarchical)
- Groups related tokens
- Represents semantic constructs

### Why Separate Parsing Phase?

**Benefits of Separation**:

| Aspect | Lexer | Parser |
|--------|-------|--------|
| **Focus** | Character-level patterns | Structural relationships |
| **Output** | Flat token stream | Hierarchical tree |
| **Concerns** | Whitespace, comments, literals | Syntax rules, nesting, grouping |
| **Testing** | Pattern matching | Structural validity |

**Example**:

Without parser (lexer does everything):
```text
"if (x > 5) { return x; }"

Lexer must:
  - Recognize keywords, operators
  - Build tree structure
  - Track nesting depth
  - Validate syntax
  → Violates single responsibility
```

With parser (separation of concerns):
```text
Lexer: characters → tokens
Parser: tokens → AST
  → Each phase has clear responsibility
```

## [2].responsibilities_and_boundaries

### Input and Output

| Aspect | Details |
|--------|---------|
| **Input** | Token stream from lexer: `[{type, value, position, metadata}, ...]` |
| **Output** | Abstract Syntax Tree: hierarchical structure of nodes |
| **Guarantee** | All tokens are consumed (no information loss) |
| **Structure** | Tree with parent/child relationships, not flat list |

**Example Flow**:
```text
Input: [{IDENTIFIER, "x"}, {ASSIGN, "="}, {NUMBER, "42"}]

Output:
{
    type: "AssignmentExpression",
    left: {type: "Identifier", name: "x"},
    operator: "=",
    right: {type: "Literal", value: 42}
}
```

### What Parser DOES

| Responsibility | Example |
|----------------|---------|
| **Group related tokens** | 3 IDENTIFIER tokens → 1 QualifiedName node |
| **Build hierarchy** | Expression tokens → BinaryExpression with left/right |
| **Handle precedence** | `2 + 3 * 4` → correct tree structure |
| **Track state** | Inside block, inside function, nesting level |
| **Map tokens to nodes** | KEYWORD_IF → IfStatement node |

### What Parser DOES NOT Do

| ❌ Not Responsibility | Why Not? | Who Does It? |
|----------------------|----------|--------------|
| **Pattern matching** | Already done by lexer | Lexical analyzer |
| **Type checking** | "Variable undefined" is semantic | Semantic analyzer |
| **Code generation** | Translation to target language | Code generator |
| **Optimization** | AST transformation | Optimizer |
| **Validation of context rules** | "Return outside function" | Validator/Semantic analyzer |

### Clear Boundaries with Other Phases

```text
┌─────────────┐
│   Lexer     │ → Identifies lexemes
└──────┬──────┘
       ↓ tokens [{type: "KEYWORD_IF", ...}, ...]
┌─────────────┐
│   Parser    │ → Builds structure
└──────┬──────┘   ❌ Does NOT validate semantics
       ↓ AST {type: "IfStatement", ...}
┌─────────────┐
│  Validator  │ → Checks context rules
└──────┬──────┘   ❌ Does NOT modify AST
       ↓ AST + errors
┌─────────────┐
│  Generator  │ → Produces output
└─────────────┘
```

**Golden Rule**: Parser **constructs** structure, validator **verifies** correctness.

## [3].core_concepts

### Token vs Node

| Concept | Definition | Example |
|---------|------------|---------|
| **Token** | Lexical unit identified by lexer | `{type: "KEYWORD_IF", value: "if"}` |
| **Node** | Semantic construct in AST | `{type: "IfStatement", condition: ..., body: ...}` |

**Relationship**:
- One token → one node (simple case)
- Multiple tokens → one node (grouping)
- One token → multiple nodes (expansion)
- Token → no node (punctuation consumed)

### Grouping (Tokens → Nodes)

**Grouping** is identifying which tokens form a semantic unit.

#### Example 1: Expression

**Tokens**:
```text
[
    {type: "IDENTIFIER", value: "x"},
    {type: "PLUS", value: "+"},
    {type: "NUMBER", value: "5"}
]
```

**Grouping**: these three tokens form a binary expression.

**Resulting Node**:
```text
{
    type: "BinaryExpression",
    operator: "+",
    left: {type: "Identifier", name: "x"},
    right: {type: "Literal", value: 5}
}
```

#### Example 2: Block Statement

**Tokens**:
```text
[
    {type: "LBRACE", value: "{"},
    {type: "KEYWORD_RETURN", value: "return"},
    {type: "IDENTIFIER", value: "x"},
    {type: "SEMICOLON", value: ";"},
    {type: "RBRACE", value: "}"}
]
```

**Grouping**: tokens from `{` to `}` form a block.

**Resulting Node**:
```text
{
    type: "BlockStatement",
    body: [
        {
            type: "ReturnStatement",
            argument: {type: "Identifier", name: "x"}
        }
    ]
}
```

### Parser State

Parsers often need to **remember context** while processing tokens.

#### State: Nesting Depth

```text
nesting_level = 0

for token in tokens:
    if token.type == LBRACE:
        nesting_level += 1
    elif token.type == RBRACE:
        nesting_level -= 1
    
    # Use nesting_level to validate structure
```

#### State: Current Context

```text
context_stack = ["global"]

for token in tokens:
    if token.type == KEYWORD_FUNCTION:
        context_stack.append("function")
    elif token.type == KEYWORD_END:
        context_stack.pop()
    
    # Use context for semantic decisions
```

### Buffers (Accumulators)

**Buffers** accumulate tokens until a closing condition is met.

#### Expression Buffer

```text
expr_buffer = []

for token in tokens:
    if token.type in EXPRESSION_TOKENS:
        expr_buffer.append(token)
    elif token.type == SEMICOLON:
        node = build_expression(expr_buffer)
        expr_buffer = []
```

**Flush condition**: semicolon, end of block, or specific delimiter.

#### Statement Buffer

```text
statement_buffer = []

for token in tokens:
    statement_buffer.append(token)
    
    if is_complete_statement(statement_buffer):
        node = build_statement(statement_buffer)
        statement_buffer = []
```

## [4].grouping_strategies

### One-to-One Mapping (Token → Node)

**Case**: token that represents a complete construct.

| Token Type | Node Type |
|------------|-----------|
| `KEYWORD_BREAK` | `BreakStatement` |
| `KEYWORD_CONTINUE` | `ContinueStatement` |
| `LITERAL_STRING` | `StringLiteral` |

**Example**:
```text
function make_node(token):
    if token.type == KEYWORD_BREAK:
        return {
            type: "BreakStatement",
            label: null
        }
```

### Many-to-One Mapping (Multiple Tokens → One Node)

**Case**: multiple tokens combine to form a single construct.

**Example: Binary Expression**

```text
Tokens: [IDENTIFIER("x"), PLUS("+"), NUMBER(5)]

→ One BinaryExpression node:
{
    type: "BinaryExpression",
    operator: "+",
    left: {type: "Identifier", name: "x"},
    right: {type: "Literal", value: 5}
}
```

**Algorithm**:
```text
function parse_expression(tokens):
    left = parse_primary(tokens[0])
    operator = tokens[1]
    right = parse_primary(tokens[2])
    
    return {
        type: "BinaryExpression",
        operator: operator.value,
        left: left,
        right: right
    }
```

### Stateful Parsing (Delimited Tokens)

**Case**: opening and closing tokens delimit internal content.

**Example: Function Declaration**

```text
Tokens:
[
    KEYWORD_FUNCTION,
    IDENTIFIER("foo"),
    LPAREN,
    IDENTIFIER("x"),
    RPAREN,
    LBRACE,
    ...,
    RBRACE
]

→ One FunctionDeclaration node:
{
    type: "FunctionDeclaration",
    id: {type: "Identifier", name: "foo"},
    params: [{type: "Identifier", name: "x"}],
    body: {type: "BlockStatement", body: [...]}
}
```

**Algorithm**:
```text
state = OUTSIDE

for token in tokens:
    if token.type == KEYWORD_FUNCTION:
        state = IN_FUNCTION_DECL
        name = next_identifier()
        params = parse_params()
    elif token.type == LBRACE and state == IN_FUNCTION_DECL:
        body = parse_block()
        create_function_node(name, params, body)
        state = OUTSIDE
```

### Series Parsing (Sequence → Collection)

**Case**: repeated constructs of the same type form a collection.

**Example: Array Literal**

```text
Tokens:
[
    LBRACKET,
    NUMBER(1),
    COMMA,
    NUMBER(2),
    COMMA,
    NUMBER(3),
    RBRACKET
]

→ One ArrayExpression node:
{
    type: "ArrayExpression",
    elements: [
        {type: "Literal", value: 1},
        {type: "Literal", value: 2},
        {type: "Literal", value: 3}
    ]
}
```

**Algorithm**:
```text
elements = []
inside_array = false

for token in tokens:
    if token.type == LBRACKET:
        inside_array = true
    elif token.type == RBRACKET:
        create_array_node(elements)
        inside_array = false
    elif inside_array and token.type != COMMA:
        elements.append(parse_element(token))
```

## [5].main_algorithm

### Core Parsing Loop (Pseudocode)

```text
function parse(tokens):
    ast = {type: "Program", body: []}
    index = 0
    context_stack = ["global"]
    buffers = {
        expression: [],
        statement: [],
        block: []
    }
    
    while index < length(tokens):
        token = tokens[index]
        
        # Determine action based on token type and context
        if token.type in STATEMENT_STARTERS:
            flush_expression_buffer()
            node = parse_statement(tokens, index)
            ast.body.append(node)
            index = node.end_index
        
        elif token.type in EXPRESSION_TOKENS:
            buffers.expression.append(token)
            index += 1
        
        elif token.type == SEMICOLON:
            flush_expression_buffer()
            index += 1
        
        elif token.type == LBRACE:
            context_stack.append("block")
            index += 1
        
        elif token.type == RBRACE:
            flush_all_buffers()
            context_stack.pop()
            index += 1
        
        else:
            index += 1
    
    # Final flush
    flush_all_buffers()
    
    return ast
```

### Buffer Management

**General flush function**:
```text
function flush_all_buffers():
    flush_expression_buffer()
    flush_statement_buffer()
    flush_block_buffer()
```

**Why flush on type change?**

```text
Input: "x = 5; if (true) { return; }"

When parser sees "if":
  - Must close previous statement (x = 5)
  - Start new statement (if)

Without flush:
  - Previous statement remains open
  - Tokens get mixed incorrectly
```

### State Management

| State | Activation | Deactivation | Purpose |
|-------|-----------|--------------|---------|
| `in_function` | `KEYWORD_FUNCTION` | `RBRACE` (matching) | Track function scope |
| `in_loop` | `KEYWORD_WHILE/FOR` | Loop end | Allow break/continue |
| `in_block` | `LBRACE` | `RBRACE` | Track nesting |

### Flush Conditions

| Event | Buffers to Flush | Reason |
|-------|------------------|--------|
| **Semicolon** | Expression, statement | Explicit delimiter |
| **Block start `{`** | All | New scope begins |
| **Block end `}`** | All | Scope closes |
| **Statement keyword** | Expression | New statement starts |
| **EOF** | All | Close open constructs |

## [6].node_construction

### Node Factory Pattern

```text
function make_node(type, attributes):
    node = {
        type: type,
        ...attributes
    }
    
    # Optional: add source location
    if attributes.token:
        node.loc = {
            start: attributes.token.position,
            end: attributes.token.end_position
        }
    
    return node
```

### Type-Specific Constructors

#### Literal Node

```text
function make_literal(token):
    return {
        type: "Literal",
        value: parse_literal_value(token),
        raw: token.value
    }
```

#### Identifier Node

```text
function make_identifier(token):
    return {
        type: "Identifier",
        name: token.value
    }
```

#### Binary Expression Node

```text
function make_binary_expr(left, operator, right):
    return {
        type: "BinaryExpression",
        operator: operator.value,
        left: left,
        right: right
    }
```

#### Function Declaration Node

```text
function make_function_decl(name, params, body):
    return {
        type: "FunctionDeclaration",
        id: make_identifier(name),
        params: [make_identifier(p) for p in params],
        body: body
    }
```

| Node Type | Required Metadata | Source |
|-----------|------------------|--------|
| `FunctionDeclaration` | `id`, `params`, `body` | Name token, param list, block |
| `IfStatement` | `test`, `consequent`, `alternate` | Condition expr, then block, else block |
| `BinaryExpression` | `operator`, `left`, `right` | Operator token, operand nodes |
| `Literal` | `value`, `raw` | Token value, original text |

## [7].flush_strategies

### Expression Flush

**Purpose**: close an accumulated expression and convert to node.

```text
function flush_expression(buffer, ast):
    if buffer.is_empty():
        return
    
    node = build_expression_from_tokens(buffer)
    ast.current_context.append(node)
    buffer.clear()
```

**When to call**:
- Semicolon encountered
- Statement keyword encountered
- Block delimiter encountered

### Statement Flush

**Purpose**: close a complete statement.

```text
function flush_statement(buffer, ast):
    if buffer.is_empty():
        return
    
    node = build_statement_from_tokens(buffer)
    ast.body.append(node)
    buffer.clear()
```

**When to call**:
- Semicolon (explicit end)
- Block end (implicit end)
- EOF

### Block Flush

**Purpose**: close a block and pop context.

```text
function flush_block(statements, context_stack):
    if statements.is_empty():
        return
    
    block_node = {
        type: "BlockStatement",
        body: statements
    }
    
    parent_context = context_stack[-2]
    parent_context.append(block_node)
    
    context_stack.pop()
    statements.clear()
```

### Flush Condition Table

| Buffer | Flush When... | Example |
|--------|---------------|---------|
| **Expression** | `;`, statement keyword, block delimiter | `x + 5;` → flush at `;` |
| **Statement** | `;`, `}`, EOF | `return x;` → flush at `;` |
| **Block** | Matching `}`, EOF | `{ ... }` → flush at `}` |

## [8].edge_cases

### Incomplete Statement at EOF

**Problem**:
```text
Input: "x = 5"  (no semicolon)
```

**Solution**: implicit flush at EOF.

```text
function parse(tokens):
    # ... main loop ...
    
    # After loop: mandatory flush
    flush_all_buffers()
```

### Unmatched Delimiters

**Problem**:
```text
Input: "{ x = 5"  (missing closing brace)
```

**Options**:

#### Option A: Error (Strict)
```text
if context_stack.length > 1 at EOF:
    raise ParseError("Unclosed block at EOF")
```

#### Option B: Implicit Close (Permissive)
```text
while context_stack.length > 1:
    flush_current_block()
    context_stack.pop()
    warnings.append("Block implicitly closed at EOF")
```

### Operator Precedence

**Problem**:
```text
Input: "2 + 3 * 4"

Incorrect: ((2 + 3) * 4) = 20
Correct: (2 + (3 * 4)) = 14
```

**Solution**: precedence climbing or Pratt parsing.

```text
function parse_expression(tokens, min_precedence):
    left = parse_primary(tokens)
    
    while current_operator_precedence() >= min_precedence:
        op = consume_operator()
        right = parse_expression(tokens, op.precedence + 1)
        left = make_binary_expr(left, op, right)
    
    return left
```

### Ambiguous Grammar

**Problem**:
```text
Input: "if (x) if (y) a(); else b();"

Which if does the else belong to?
```

**Solution**: dangling else rule (else binds to nearest if).

```text
function parse_if_statement():
    # ...
    if next_token() == KEYWORD_ELSE:
        # Binds to most recent if
        alternate = parse_statement()
```

## [9].grammar_relationship

### Grammar as Construction Guide

Grammar defines valid structures, parser **uses it as template**, but doesn't validate all rules.

```text
Grammar Rule:
    IfStatement:
        'if' '(' Expression ')' Statement ('else' Statement)?

Parser Action:
    function parse_if_statement():
        expect(KEYWORD_IF)
        expect(LPAREN)
        test = parse_expression()
        expect(RPAREN)
        consequent = parse_statement()
        alternate = parse_else_clause_if_present()
        
        return make_if_statement(test, consequent, alternate)
```

### Child Constraints

**Grammar specifies allowed children**:

```text
Grammar:
    FunctionDeclaration:
        id: Identifier
        params: [Identifier]*
        body: BlockStatement

Parser constructs matching structure:
    {
        type: "FunctionDeclaration",
        id: {type: "Identifier", ...},      # ← Grammar requires Identifier
        params: [{type: "Identifier", ...}], # ← Grammar requires list of Identifiers
        body: {type: "BlockStatement", ...}  # ← Grammar requires BlockStatement
    }
```

### Parser Builds, Validator Validates

| Phase | Action | Example |
|-------|--------|---------|
| **Parser** | Constructs node according to grammar structure | Creates IfStatement with test, consequent |
| **Validator** | Verifies semantic rules | Checks that test is boolean expression |

**Separation of concerns**:
- Parser: "This is an if statement with condition x"
- Validator: "Condition x must be boolean type"

## [10].mvp_implementation

### Minimal Viable Parser

**Supported constructs** (example for simple language):
- Variable declarations
- Assignment expressions
- Binary expressions (`+`, `-`, `*`, `/`)
- Literals (numbers, strings)
- Identifiers

**Example**:
```text
function parse_mvp(tokens):
    ast = {type: "Program", body: []}
    index = 0
    
    while index < length(tokens):
        token = tokens[index]
        
        if token.type == KEYWORD_VAR:
            node = parse_variable_declaration(tokens, index)
            ast.body.append(node)
            index = node.end_index
        
        elif token.type == IDENTIFIER:
            # Assignment or expression
            if peek_next(tokens, index) == ASSIGN:
                node = parse_assignment(tokens, index)
            else:
                node = parse_expression(tokens, index)
            ast.body.append(node)
            index = node.end_index
        
        else:
            index += 1
    
    return ast
```

### Incremental Addition Strategy

#### Phase 1.1: Control Flow
Add: `if`, `while`, `for` statements

```text
elif token.type == KEYWORD_IF:
    node = parse_if_statement(tokens, index)
    ast.body.append(node)
```

#### Phase 1.2: Functions
Add: function declarations and calls

```text
elif token.type == KEYWORD_FUNCTION:
    node = parse_function_declaration(tokens, index)
    ast.body.append(node)
```

#### Phase 1.3: Advanced Expressions
Add: ternary operator, logical operators, member access

```text
# In parse_expression:
if operator.type == QUESTION:
    return parse_ternary_expression(left, tokens, index)
```

### Completion Criteria

Parser MVP is complete when it:

1. Converts basic token stream to AST
2. Handles fundamental constructs (declarations, expressions, assignments)
3. Manages operator precedence correctly
4. Performs final flush at EOF
5. Generates well-formed AST: `{type: "Program", body: [...]}`
6. Passes basic tests (variable declaration, simple expression)

## [11].antipatterns

### Antipattern 1: Semantic Validation in Parser

```text
❌ Don't do this:
function parse_if_statement():
    test = parse_expression()
    
    # Semantic check in parser
    if test.type != "BooleanExpression":
        raise Error("If condition must be boolean")
    
    # ...
```

**Problem**: mixes construction (parser) with validation (semantic analyzer).

**Solution**: parse constructs, validate semantics later.

```text
✅ Parser only constructs:
function parse_if_statement():
    test = parse_expression()  # accept any expression
    return make_if_statement(test, consequent, alternate)

✅ Validator checks semantics:
function validate_if_statement(node):
    if not is_boolean_type(node.test):
        errors.append("If condition must be boolean")
```

### Antipattern 2: Global Mutable State

```text
❌ Global state:
current_ast = null  # global

function parse(tokens):
    for token in tokens:
        current_ast.append(process(token))  # modifies global

# Problem: tests interfere with each other
```

**Solution**: local state or explicit context.

```text
✅ Local state:
function parse(tokens):
    ast = {type: "Program", body: []}  # local
    # ...
    return ast
```

### Antipattern 3: Missing Final Flush

```text
❌ No flush at EOF:
function parse(tokens):
    for token in tokens:
        # ...
    return ast  # ← incomplete constructs lost
```

**Solution**: explicit flush after loop.

```text
✅ Final flush:
function parse(tokens):
    for token in tokens:
        # ...
    
    flush_all_buffers()  # ← close open constructs
    return ast
```

### Antipattern 4: Hardcoded Node Types

```text
❌ Hardcoded:
function make_node(token):
    if token.type == KEYWORD_IF:
        return {type: "IfStatement", ...}
    elif token.type == KEYWORD_WHILE:
        return {type: "WhileStatement", ...}
    # ... 50 more elif
```

**Solution**: dispatch table.

```text
✅ Dispatch table:
NODE_BUILDERS = {
    KEYWORD_IF: build_if_statement,
    KEYWORD_WHILE: build_while_statement,
    # ...
}

function make_node(token):
    builder = NODE_BUILDERS[token.type]
    return builder(token)
```

### Antipattern 5: Mixing Parsing Levels

```text
❌ Statement parser handling expression details:
function parse_statement(tokens):
    # ...
    # Handling operator precedence here
    if operator == PLUS:
        # detailed expression parsing
```

**Problem**: violates separation (statements vs expressions).

**Solution**: delegate to expression parser.

```text
✅ Delegation:
function parse_statement(tokens):
    if token.type == IDENTIFIER:
        expr = parse_expression(tokens)  # delegate
        return make_expression_statement(expr)
```

## Conclusion

The **parser** transforms flat token streams into hierarchical abstract syntax trees, bridging lexical analysis and semantic analysis. Core principles:

1. **Grouping**: transform flat tokens into hierarchical structure
2. **State management**: handle multi-token constructs
3. **Explicit flushing**: close open constructs (delimiters, type changes, EOF)
4. **Clear separation**: parser constructs, validator validates
5. **Incremental development**: MVP first, then iterate

**Key Takeaways**:

- Parser focuses on **syntactic structure**, not semantic correctness
- Use **grammar as template**, not validation rulebook
- **Flush explicitly** at boundaries (delimiters, EOF)
- **Delegate validation** to separate phase
- Test **structure independently** of specific content

**Next Steps**:

1. Implement MVP parser (basic constructs)
2. Test each grouping strategy
3. Add advanced constructs incrementally
4. Move to semantic analysis/validation phase

Remember: parser should be **robust but permissive**. Build what you see, validate later. Don't try to be parser + validator simultaneously.
