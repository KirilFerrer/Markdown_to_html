# Implementación del Módulo `parser`

## [1].motivacion

### El Rol del Parser en el Pipeline

El parser es el **puente entre sintaxis y semántica**. Mientras que el lexer identifica *qué tipo* de línea es cada una, el parser entiende *qué significan* en conjunto.

```text
┌──────────────┐
│  lexer.py    │  ← "Esta línea es TEXT"
└──────┬───────┘
       ↓ tokens
┌──────────────┐
│  parser.py   │  ← "Tres TEXT consecutivos = un párrafo"
└──────┬───────┘
       ↓ AST
┌──────────────┐
│ validator.py │  ← "¿Este árbol cumple las reglas?"
└──────────────┘
```

### Diferencia Entre Tokens y AST

#### Tokens (Output del Lexer)

```python
[
    {"type": "TEXT", "line": 1, "meta": {"content": "Primera línea"}},
    {"type": "TEXT", "line": 2, "meta": {"content": "Segunda línea"}},
    {"type": "BLANK_LINE", "line": 3, "meta": {}}
]
```

**Características**:
- Lista plana (sin jerarquía)
- Un token por línea
- Solo clasificación, sin relaciones

#### AST (Output del Parser)

```python
{
    "type": "document",
    "children": [
        {
            "type": "paragraph",
            "children": [
                {"type": "text", "value": "Primera línea Segunda línea"}
            ]
        }
    ]
}
```

**Características**:
- Estructura arbórea (jerárquica)
- Agrupa tokens relacionados
- Representa construcciones semánticas (párrafos, listas, etc.)

### ¿Por Qué Viene Después del Lexer?

**Separación de responsabilidades**:

| Fase | Pregunta que Responde | Ejemplo |
|------|----------------------|---------|
| **Lexer** | "¿Qué tipo de línea es esta?" | `"# Título"` → token `HEADING_ATX` |
| **Parser** | "¿Cómo se relacionan estas líneas?" | Tres tokens `TEXT` → un nodo `paragraph` |
| **Validator** | "¿Cumple las reglas del lenguaje?" | "¿Hay headings dentro de listas?" |

**Intentar hacer parsing durante lexing**:
```python
# ❌ Antipatrón: lexer intentando agrupar
def tokenize(text):
    tokens = []
    paragraph_buffer = []  # ← esto NO va en el lexer
    for line in text.split("\n"):
        if is_text(line):
            paragraph_buffer.append(line)  # ← responsabilidad del parser
        # ...
```

**Problema**: mezcla identificación (lexer) con agrupación (parser).

### Beneficios de la Fase de Parsing Separada

1. **Modularidad**: puedes cambiar cómo se agrupan tokens sin tocar el lexer
2. **Testing independiente**: testea lexer con tokens, parser con AST
3. **Reutilización**: el mismo lexer puede alimentar múltiples parsers (strict, permissive, etc.)
4. **Debugging más fácil**: puedes inspeccionar tokens antes del parsing

## [2].responsabilidad_y_limites

### Entrada y Salida del Parser

| Aspecto | Detalle |
|---------|---------|
| **Entrada** | Lista de tokens de `lexer.tokenize()` |
| **Salida** | AST: `{"type": "document", "children": [...]}` |
| **Garantía** | Todos los tokens se consumen (ninguno se pierde) |
| **Estructura** | Árbol con nodos padre/hijo, no lista plana |

### Qué Hace el Parser

| Responsabilidad | Ejemplo |
|-----------------|---------|
| **Agrupar tokens relacionados** | 3 tokens `TEXT` → 1 nodo `paragraph` |
| **Construir jerarquía** | Tokens `LIST_ITEM` → nodo `list` con hijos `list_item` |
| **Manejar estados** | `CODE_FENCE_START` abre, `CODE_FENCE_END` cierra |
| **Mapear tokens → nodos** | Token `HEADING_ATX` → nodo `heading` |
| **Extraer metadata** | `level` del heading, `lang` del code block |

### Qué NO Hace el Parser

| ❌ No Responsabilidad | ¿Por Qué No? | ¿Quién Lo Hace? |
|----------------------|--------------|-----------------|
| **Validar regex** | Ya lo hizo el lexer | `lexer.py` |
| **Verificar reglas contextuales** | "No headings en listas" es validación | `validator.py` |
| **Renderizar HTML** | Es conversión, no construcción | `renderer.py` |
| **Parsear inline (énfasis, enlaces)** | Es fase separada | `inline.py` (futuro) |
| **Optimizar AST** | Es post-procesamiento | Fase opcional |

### Límites Claros con Otros Módulos

```text
┌────────────┐
│  lexer     │ → identifica líneas
└─────┬──────┘
      ↓ tokens ["HEADING", "TEXT", ...]
┌────────────┐
│  parser    │ → agrupa en árbol
└─────┬──────┘     ❌ NO valida reglas
      ↓ AST {type: "document", children: [...]}
┌────────────┐
│ validator  │ → valida reglas contextuales
└─────┬──────┘     ❌ NO modifica AST
      ↓ AST + errores
┌────────────┐
│ renderer   │ → convierte a HTML
└────────────┘
```

**Regla de oro**: parser **construye** estructura, validator **verifica** corrección.

## [3].conceptos_clave

### Token vs Nodo

| Concepto | Definición | Ejemplo |
|----------|------------|---------|
| **Token** | Línea identificada por el lexer | `{"type": "TEXT", "meta": {"content": "hola"}}` |
| **Nodo** | Construcción semántica del AST | `{"type": "paragraph", "children": [...]}` |

**Relación**:
- Un token puede convertirse en un nodo (`HEADING` → `heading`)
- Varios tokens pueden colapsar en un nodo (3 `TEXT` → 1 `paragraph`)
- Un token puede no generar nodo (`BLANK_LINE` solo separa bloques)

### Agrupación (Tokens → Nodos)

La agrupación es el proceso de **identificar qué tokens forman una unidad semántica**.

#### Ejemplo 1: Párrafo

**Tokens**:
```python
[
    {"type": "TEXT", "meta": {"content": "Línea uno"}},
    {"type": "TEXT", "meta": {"content": "Línea dos"}},
    {"type": "BLANK_LINE", "meta": {}}
]
```

**Agrupación**: los dos `TEXT` forman un párrafo (separado por `BLANK_LINE`).

**Nodo resultante**:
```python
{
    "type": "paragraph",
    "children": [
        {"type": "text", "value": "Línea uno Línea dos"}
    ]
}
```

#### Ejemplo 2: Code Block

**Tokens**:
```python
[
    {"type": "CODE_FENCE_START", "meta": {"lang": "python"}},
    {"type": "TEXT", "meta": {"content": "print('hola')"}},
    {"type": "CODE_FENCE_END", "meta": {}}
]
```

**Agrupación**: desde `CODE_FENCE_START` hasta `CODE_FENCE_END` es un bloque.

**Nodo resultante**:
```python
{
    "type": "code_block",
    "meta": {
        "lang": "python",
        "content": "print('hola')"
    },
    "children": []
}
```

### Estados del Parser

El parser necesita **recordar contexto** mientras procesa tokens.

#### Estado: Dentro de Code Fence

```python
dentro_fence = False  # bandera de estado

for token in tokens:
    if token["type"] == "CODE_FENCE_START":
        dentro_fence = True
    elif token["type"] == "CODE_FENCE_END":
        dentro_fence = False
    elif dentro_fence:
        # acumular líneas de código
```

#### Estado: Nivel de Indentación (Listas)

```python
indent_stack = [0]  # stack de niveles de indent

for token in tokens:
    if token["type"] == "LIST_ITEM":
        indent = len(token["meta"]["indent"])
        if indent > indent_stack[-1]:
            # abrir sublista
        elif indent < indent_stack[-1]:
            # cerrar sublista
```

### Buffers (Acumuladores)

Los buffers **acumulan tokens** hasta que se cumpla una condición de cierre (flush).

#### Buffer de Párrafo

```python
paragraph_buffer = []

for token in tokens:
    if token["type"] == "TEXT":
        paragraph_buffer.append(token)  # acumular
    elif token["type"] == "BLANK_LINE":
        flush_paragraph(paragraph_buffer)  # cerrar y vaciar
        paragraph_buffer = []
```

**Condición de flush**: `BLANK_LINE`, cambio de tipo de bloque, o EOF.

#### Buffer de Code Block

```python
code_lines = []
inside_fence = False

for token in tokens:
    if token["type"] == "CODE_FENCE_START":
        inside_fence = True
        lang = token["meta"]["lang"]
    elif token["type"] == "CODE_FENCE_END":
        flush_code_block(code_lines, lang)
        code_lines = []
        inside_fence = False
    elif inside_fence:
        code_lines.append(token["meta"]["content"])
```

## [4].estrategias_de_agrupacion

### Mapeo 1:1 (Token → Nodo)

**Caso**: token que representa un bloque completo en una línea.

| Token | Nodo |
|-------|------|
| `HEADING_ATX` | `heading` |
| `HR` | `hr` |

**Ejemplo**:
```python
def make_node(token):
    if token["type"] == "HEADING_ATX":
        return {
            "type": "heading",
            "level": len(token["meta"]["level"]),
            "children": [
                {"type": "text", "value": token["meta"]["content"]}
            ]
        }
    elif token["type"] == "HR":
        return {"type": "hr", "children": []}
```

### Mapeo N:1 (Múltiples Tokens → Un Nodo)

**Caso**: varios tokens del mismo tipo que forman un bloque.

**Ejemplo: Párrafo**

```python
# Tokens
[
    {"type": "TEXT", "meta": {"content": "A"}},
    {"type": "TEXT", "meta": {"content": "B"}},
    {"type": "TEXT", "meta": {"content": "C"}}
]

# → Un solo nodo paragraph
{
    "type": "paragraph",
    "children": [{"type": "text", "value": "A B C"}]
}
```

**Algoritmo**:
```text
buffer ← []
para cada token:
    si token.type == "TEXT":
        buffer.append(token)
    sino:
        si buffer no vacío:
            crear_nodo_paragraph(buffer)
            vaciar(buffer)
```

### Mapeo con Estado (Tokens Delimitados)

**Caso**: token de inicio y fin delimitan contenido interno.

**Ejemplo: Code Fence**

```python
# Tokens
[
    {"type": "CODE_FENCE_START", "meta": {"lang": "js"}},
    {"type": "TEXT", "meta": {"content": "const x = 1"}},
    {"type": "TEXT", "meta": {"content": "console.log(x)"}},
    {"type": "CODE_FENCE_END", "meta": {}}
]

# → Un nodo code_block
{
    "type": "code_block",
    "meta": {"lang": "js", "content": "const x = 1\nconsole.log(x)"},
    "children": []
}
```

**Algoritmo**:
```text
estado ← FUERA_DE_FENCE
buffer_código ← []

para cada token:
    si token.type == "CODE_FENCE_START":
        estado ← DENTRO_DE_FENCE
        lang ← token.meta.lang
    sino si token.type == "CODE_FENCE_END":
        crear_nodo_code_block(buffer_código, lang)
        estado ← FUERA_DE_FENCE
    sino si estado == DENTRO_DE_FENCE:
        buffer_código.append(token.meta.content)
```

### Mapeo de Series (Secuencia de Tokens → Contenedor)

**Caso**: múltiples tokens del mismo tipo que forman una colección.

**Ejemplo: Lista**

```python
# Tokens
[
    {"type": "LIST_ITEM", "meta": {"content": "Item 1"}},
    {"type": "LIST_ITEM", "meta": {"content": "Item 2"}},
    {"type": "LIST_ITEM", "meta": {"content": "Item 3"}}
]

# → Un nodo list con múltiples list_item
{
    "type": "list",
    "children": [
        {"type": "list_item", "children": [{"type": "text", "value": "Item 1"}]},
        {"type": "list_item", "children": [{"type": "text", "value": "Item 2"}]},
        {"type": "list_item", "children": [{"type": "text", "value": "Item 3"}]}
    ]
}
```

**Algoritmo**:
```text
lista_actual ← null
items ← []

para cada token:
    si token.type == "LIST_ITEM":
        item ← crear_list_item(token)
        items.append(item)
    sino:
        si items no vacío:
            lista_actual ← crear_list(items)
            agregar_a_documento(lista_actual)
            items ← []
```

## [5].algoritmo_principal

### Pseudocódigo del Loop Principal

```text
función parse(tokens):
    documento ← {type: "document", children: []}
    buffer_párrafo ← []
    buffer_lista ← []
    estado_fence ← {activo: False, lang: "", contenido: []}
    
    para cada token en tokens:
        tipo ← token.type
        
        # Caso 1: Code fence
        si tipo == "CODE_FENCE_START":
            flush_all_buffers()
            estado_fence ← {activo: True, lang: token.meta.lang, contenido: []}
        
        sino si tipo == "CODE_FENCE_END":
            nodo ← make_code_block(estado_fence)
            documento.children.append(nodo)
            estado_fence ← {activo: False, lang: "", contenido: []}
        
        sino si estado_fence.activo:
            estado_fence.contenido.append(token.meta.content)
        
        # Caso 2: Heading (1:1)
        sino si tipo == "HEADING_ATX":
            flush_all_buffers()
            nodo ← make_heading(token)
            documento.children.append(nodo)
        
        # Caso 3: HR (1:1)
        sino si tipo == "HR":
            flush_all_buffers()
            nodo ← make_hr()
            documento.children.append(nodo)
        
        # Caso 4: Lista (serie)
        sino si tipo == "LIST_ITEM":
            flush_paragraph(buffer_párrafo)
            buffer_lista.append(token)
        
        # Caso 5: Texto (acumular en párrafo)
        sino si tipo == "TEXT":
            flush_list(buffer_lista)
            buffer_párrafo.append(token)
        
        # Caso 6: Blank line (separador)
        sino si tipo == "BLANK_LINE":
            flush_all_buffers()
    
    # Flush final (EOF)
    flush_all_buffers()
    
    retornar documento
```

### Manejo de Buffers

**Función auxiliar para flush general**:
```text
función flush_all_buffers():
    flush_paragraph(buffer_párrafo)
    flush_list(buffer_lista)
```

**¿Por qué flush al cambiar de tipo?**

```python
# Entrada
"""
Texto de párrafo
# Heading
"""

# Tokens
[
    {"type": "TEXT", ...},      # acumula en buffer_párrafo
    {"type": "HEADING_ATX", ...} # ← FLUSH: cierra párrafo antes de heading
]
```

Sin flush, el párrafo quedaría "abierto" y el heading se perdería.

### Estados: Cuándo Activar/Desactivar

| Estado | Activación | Desactivación | Propósito |
|--------|-----------|---------------|-----------|
| `dentro_fence` | `CODE_FENCE_START` | `CODE_FENCE_END` | Capturar líneas literales |
| `lista_activa` | Primer `LIST_ITEM` | Token no-`LIST_ITEM` | Agrupar items |
| `párrafo_activo` | Primer `TEXT` | `BLANK_LINE` o cambio tipo | Agrupar líneas |

### Condiciones de Flush

| Evento | Buffers a Flush | Razón |
|--------|-----------------|-------|
| `BLANK_LINE` | Todos | Separador explícito |
| Cambio de tipo de bloque | Todos | Nuevo bloque empieza |
| `CODE_FENCE_START` | Párrafo, lista | Fence tiene prioridad |
| EOF (fin de tokens) | Todos | Cerrar bloques abiertos |

## [6].make_node_detallado

### Función `make_node`: Token → Nodo

```python
def make_node(token):
    """Convierte un token en un nodo del AST."""
    tipo_token = token["type"]
    
    # Mapeo tipo token → tipo nodo
    mapeo = {
        "HEADING_ATX": "heading",
        "HR": "hr",
        "LIST_ITEM": "list_item",
        # ...
    }
    
    tipo_nodo = mapeo.get(tipo_token)
    
    if tipo_nodo == "heading":
        return make_heading(token)
    elif tipo_nodo == "hr":
        return make_hr(token)
    elif tipo_nodo == "list_item":
        return make_list_item(token)
    # ...
```

### Constructores Específicos por Tipo

#### `make_heading(token)`

```python
def make_heading(token):
    level = len(token["meta"]["level"])  # contar símbolos #
    content = token["meta"]["content"]
    
    return {
        "type": "heading",
        "level": level,  # 1-6
        "children": [
            {"type": "text", "value": content}
        ]
    }
```

**Ejemplo**:
```python
# Input token
{"type": "HEADING_ATX", "meta": {"level": "##", "content": "Intro"}}

# Output nodo
{
    "type": "heading",
    "level": 2,
    "children": [{"type": "text", "value": "Intro"}]
}
```

#### `make_hr(token)`

```python
def make_hr(token):
    return {
        "type": "hr",
        "children": []  # sin hijos
    }
```

**Ejemplo**:
```python
# Input token
{"type": "HR", "meta": {}}

# Output nodo
{"type": "hr", "children": []}
```

#### `make_paragraph(tokens)`

```python
def make_paragraph(tokens):
    """Crea nodo paragraph desde múltiples tokens TEXT."""
    # Unir contenido de todos los tokens
    lineas = [t["meta"]["content"] for t in tokens]
    contenido = " ".join(lineas)
    
    return {
        "type": "paragraph",
        "children": [
            {"type": "text", "value": contenido}
        ]
    }
```

**Ejemplo**:
```python
# Input tokens
[
    {"type": "TEXT", "meta": {"content": "Primera."}},
    {"type": "TEXT", "meta": {"content": "Segunda."}}
]

# Output nodo
{
    "type": "paragraph",
    "children": [{"type": "text", "value": "Primera. Segunda."}]
}
```

#### `make_code_block(lang, lines)`

```python
def make_code_block(lang, lines):
    return {
        "type": "code_block",
        "meta": {
            "lang": lang or "",
            "content": "\n".join(lines)
        },
        "children": []
    }
```

**Ejemplo**:
```python
# Input
lang = "python"
lines = ["x = 1", "print(x)"]

# Output nodo
{
    "type": "code_block",
    "meta": {
        "lang": "python",
        "content": "x = 1\nprint(x)"
    },
    "children": []
}
```

### Asignación de Metadata

| Tipo de Nodo | Metadata Requerido | Fuente |
|--------------|-------------------|--------|
| `heading` | `level` (1-6) | Contar símbolos `#` del token |
| `code_block` | `lang`, `content` | Token `CODE_FENCE_START` y líneas acumuladas |
| `list` | `ordered` (bool) | Tipo de marcador (-, *, + vs 1., 2.) |
| `paragraph` | — | (no tiene meta) |
| `hr` | — | (no tiene meta) |

## [7].flush_strategies

### `flush_paragraph(buffer)`

**Propósito**: cerrar un párrafo acumulado y agregarlo al documento.

```python
def flush_paragraph(buffer, documento):
    if not buffer:
        return  # nada que hacer
    
    nodo = make_paragraph(buffer)
    documento["children"].append(nodo)
    buffer.clear()
```

**Cuándo llamar**:
- Al encontrar `BLANK_LINE`
- Al encontrar token de otro tipo (heading, HR, etc.)
- Al final del documento (EOF)

**Ejemplo**:
```python
buffer = [
    {"type": "TEXT", "meta": {"content": "A"}},
    {"type": "TEXT", "meta": {"content": "B"}}
]

flush_paragraph(buffer, documento)

# documento.children ahora tiene:
# [{"type": "paragraph", "children": [{"type": "text", "value": "A B"}]}]
```

### `flush_list(buffer)`

**Propósito**: cerrar una lista acumulada (múltiples `LIST_ITEM` → un nodo `list`).

```python
def flush_list(buffer, documento):
    if not buffer:
        return
    
    items = []
    for token in buffer:
        item_node = make_list_item(token)
        items.append(item_node)
    
    list_node = {
        "type": "list",
        "ordered": False,  # detectar de marcador
        "children": items
    }
    
    documento["children"].append(list_node)
    buffer.clear()
```

**Cuándo llamar**:
- Al encontrar token que no es `LIST_ITEM`
- Al encontrar `BLANK_LINE` después de lista
- Al final del documento

### `flush_code_block(estado_fence)`

**Propósito**: cerrar un bloque de código delimitado.

```python
def flush_code_block(estado, documento):
    nodo = {
        "type": "code_block",
        "meta": {
            "lang": estado["lang"],
            "content": "\n".join(estado["contenido"])
        },
        "children": []
    }
    
    documento["children"].append(nodo)
    
    # Resetear estado
    estado["activo"] = False
    estado["lang"] = ""
    estado["contenido"] = []
```

**Cuándo llamar**:
- Al encontrar `CODE_FENCE_END`
- (Opcional) Al final del documento si fence quedó sin cerrar

### Tabla de Condiciones de Flush

| Buffer | Flush Cuando... | Ejemplo |
|--------|----------------|---------|
| **Párrafo** | `BLANK_LINE`, cambio de tipo, EOF | `TEXT` → `HEADING` |
| **Lista** | Token no-`LIST_ITEM`, `BLANK_LINE`, EOF | `LIST_ITEM` → `TEXT` |
| **Code Fence** | `CODE_FENCE_END`, EOF | ` ``` ` → ` ``` ` |

## [8].casos_especiales

### Párrafo sin `BLANK_LINE` al Final (EOF)

**Problema**:
```markdown
# Heading
Último párrafo sin línea en blanco al final
```

**Tokens**:
```python
[
    {"type": "HEADING_ATX", ...},
    {"type": "TEXT", "meta": {"content": "Último párrafo..."}}
    # ← EOF aquí, sin BLANK_LINE
]
```

**Solución**: flush obligatorio al terminar el loop.

```python
for token in tokens:
    # ... procesamiento ...

# Después del loop: flush final
flush_all_buffers()
```

### Code Fence sin Cerrar

**Problema**:
```markdown
```python
x = 1
# ← EOF sin ```
```

**Opciones**:

#### Opción A: Error (Strict)
```python
if estado_fence["activo"]:
    raise ParseError("Code fence sin cerrar en EOF")
```

#### Opción B: Cerrar Implícito (Permissive)
```python
if estado_fence["activo"]:
    flush_code_block(estado_fence, documento)
    warnings.append("Code fence cerrado implícitamente en EOF")
```

**Decisión para MVP**: Opción B (permissive), emitir warning.

### Listas con Cambio de Marcador

**Problema**:
```markdown
- Item con guion
* Item con asterisco
+ Item con plus
```

**¿Son una lista o tres listas?**

#### Opción A: Una Lista (CommonMark)
Todos los marcadores (`-`, `*`, `+`) se consideran equivalentes.

```python
{
    "type": "list",
    "children": [
        {"type": "list_item", "children": [{"type": "text", "value": "Item con guion"}]},
        {"type": "list_item", "children": [{"type": "text", "value": "Item con asterisco"}]},
        {"type": "list_item", "children": [{"type": "text", "value": "Item con plus"}]}
    ]
}
```

#### Opción B: Tres Listas (Strict)
Cambio de marcador rompe la lista.

**Decisión para MVP**: Opción A (CommonMark behavior).

### Headings Consecutivos sin Párrafo

**Problema**:
```markdown
# H1
## H2
### H3
```

**Tokens**:
```python
[
    {"type": "HEADING_ATX", "meta": {"level": "#", ...}},
    {"type": "HEADING_ATX", "meta": {"level": "##", ...}},
    {"type": "HEADING_ATX", "meta": {"level": "###", ...}}
]
```

**Comportamiento correcto**: cada heading es un nodo independiente (sin agrupación).

```python
{
    "type": "document",
    "children": [
        {"type": "heading", "level": 1, ...},
        {"type": "heading", "level": 2, ...},
        {"type": "heading", "level": 3, ...}
    ]
}
```

**No hacer**: intentar agrupar headings en jerarquía automáticamente (eso es trabajo de un procesador semántico, no del parser).

## [9].relacion_con_grammar

### GRAMMAR Guía, No Valida

El parser **consulta** `GRAMMAR` de `spec.py` para saber qué estructura crear, pero **no valida** que se cumplan las reglas.

```python
# spec.py
GRAMMAR = {
    "heading": {
        "children": ["text"],
        "meta": ["level"]
    }
}

# parser.py
def make_heading(token):
    # Consulta GRAMMAR para saber estructura esperada
    spec = GRAMMAR["heading"]
    
    return {
        "type": "heading",
        "level": len(token["meta"]["level"]),  # meta requerido
        "children": [
            {"type": "text", "value": token["meta"]["content"]}
        ]  # children esperados
    }
```

### Children Permitidos por Tipo

**Parser usa GRAMMAR como template**:

```python
def make_node_with_children(tipo_nodo, hijos):
    spec = GRAMMAR[tipo_nodo]
    tipos_permitidos = spec["children"]
    
    # Parser NO valida, solo construye
    return {
        "type": tipo_nodo,
        "children": hijos  # ← puede incluir tipos no permitidos
    }
```

**Validator después verifica**:

```python
def validate_node(nodo):
    spec = GRAMMAR[nodo["type"]]
    tipos_permitidos = spec["children"]
    
    for hijo in nodo["children"]:
        if hijo["type"] not in tipos_permitidos:
            return Error(f"{hijo['type']} no permitido en {nodo['type']}")
```

### Metadata Esperado por Tipo

```python
# spec.py
GRAMMAR = {
    "code_block": {
        "children": [],
        "meta": ["lang", "content"]  # ← metadata esperado
    }
}

# parser.py
def make_code_block(lang, lines):
    # Parser asigna metadata según GRAMMAR
    return {
        "type": "code_block",
        "meta": {
            "lang": lang,      # ← esperado por GRAMMAR
            "content": "\n".join(lines)  # ← esperado por GRAMMAR
        },
        "children": []
    }
```

### Parser Construye, Validator Valida

| Fase | Acción | Ejemplo |
|------|--------|---------|
| **Parser** | Construye nodo con metadata | `{"type": "heading", "level": 2, ...}` |
| **Validator** | Verifica que `level` esté en rango 1-6 | `if level > 6: error` |

**Separación de responsabilidades**:
- Parser: "Este es un heading de nivel 7" (construye lo que ve)
- Validator: "Nivel 7 no es válido" (valida contra reglas)

## [10].mvp_parser

### Mínimo Viable: HEADING + PARAGRAPH + BLANK_LINE

**Tokens soportados**:
```python
BLOCK_ORDER = ["HEADING_ATX", "BLANK_LINE", "TEXT"]
```

**Nodos generados**:
```python
NODES = ["document", "heading", "paragraph", "text"]
```

**Funcionalidad mínima**:
```python
def parse(tokens):
    documento = {"type": "document", "children": []}
    buffer_parrafo = []
    
    for token in tokens:
        if token["type"] == "HEADING_ATX":
            flush_paragraph(buffer_parrafo, documento)
            nodo = make_heading(token)
            documento["children"].append(nodo)
        
        elif token["type"] == "TEXT":
            buffer_parrafo.append(token)
        
        elif token["type"] == "BLANK_LINE":
            flush_paragraph(buffer_parrafo, documento)
    
    flush_paragraph(buffer_parrafo, documento)  # flush final
    return documento
```

**Ejemplo funcional**:
```markdown
# Título

Este es un párrafo.

## Subtítulo

Otro párrafo.
```

→ AST completo con headings y párrafos ✅

### Orden de Agregar el Resto

#### Fase 1.1: HR

**Cambio**: agregar caso para token `HR`.

```python
elif token["type"] == "HR":
    flush_paragraph(buffer_parrafo, documento)
    nodo = make_hr()
    documento["children"].append(nodo)
```

**Testing**: línea `---` genera nodo `hr`.

#### Fase 1.2: CODE_FENCE

**Cambios**:
- Agregar estado `dentro_fence`
- Agregar buffer `code_lines`
- Manejar tokens `CODE_FENCE_START` y `CODE_FENCE_END`

```python
estado_fence = {"activo": False, "lang": "", "contenido": []}

# En el loop
if token["type"] == "CODE_FENCE_START":
    flush_paragraph(buffer_parrafo, documento)
    estado_fence = {"activo": True, "lang": token["meta"]["lang"], "contenido": []}

elif token["type"] == "CODE_FENCE_END":
    flush_code_block(estado_fence, documento)

elif estado_fence["activo"]:
    estado_fence["contenido"].append(token["meta"]["content"])
```

#### Fase 1.3: LIST

**Cambios**:
- Agregar buffer `buffer_lista`
- Manejar token `LIST_ITEM`
- Crear función `flush_list`

```python
buffer_lista = []

# En el loop
elif token["type"] == "LIST_ITEM":
    flush_paragraph(buffer_parrafo, documento)
    buffer_lista.append(token)

# Antes de otros tokens
else:
    flush_list(buffer_lista, documento)
```

### Criterio de "Parser MVP Completo"

El parser está listo cuando:

1. Convierte tokens básicos en AST (`HEADING`, `TEXT`, `BLANK_LINE`)
2. Agrupa correctamente tokens `TEXT` en párrafos
3. Hace flush al encontrar `BLANK_LINE`
4. Hace flush final en EOF
5. Genera AST bien formado: `{"type": "document", "children": [...]}`
6. Pasa tests básicos (heading + párrafo → HTML)

Con esto, puedes pasar a implementar `validator.py`.

## [11].antipatrones

### Antipatrón 1: Validar Reglas Contextuales en Parser

```python
# ❌ No hacer esto
def parse(tokens):
    nivel_previo = 0
    for token in tokens:
        if token["type"] == "HEADING_ATX":
            nivel = len(token["meta"]["level"])
            if nivel > nivel_previo + 1:  # ← validación contextual
                raise Error("Heading incrementa más de 1 nivel")
            nivel_previo = nivel
```

**Problema**: mezcla construcción (parser) con validación (validator).

**Solución**: parser construye, validator valida después.

```python
# ✅ Parser solo construye
def parse(tokens):
    for token in tokens:
        if token["type"] == "HEADING_ATX":
            nodo = make_heading(token)  # construye sin validar
            documento["children"].append(nodo)

# ✅ Validator valida después
def validate(ast):
    nivel_previo = 0
    for nodo in ast["children"]:
        if nodo["type"] == "heading":
            if nodo["level"] > nivel_previo + 1:
                warnings.append("MD001: heading incrementa más de 1")
```

### Antipatrón 2: Estados Globales Mutables

```python
# ❌ Estado global mutable
buffer_parrafo = []  # global

# Problema: tests no son independientes

def test_parse2():
    parse([...])  # ← usa buffer del test anterior
```

**Solución**: estado local o contexto explícito.

```python

    buffer_parrafo = []  # local a la función
    # ...
```

### Antipatrón 3: No Hacer Flush Final

```python
# ❌ Olvida flush en EOF
def parse(tokens):
    for token in tokens:
        # ...
    return documento  # ← párrafo abierto se pierde
```

**Problema**: último párrafo sin `BLANK_LINE` se pierde.

**Solución**: flush explícito después del loop.

```python

        # ...
    
    flush_all_buffers()  # ← cerrar bloques abiertos
    return documento
```

### Antipatrón 4: Hardcodear Tipos de Nodo

```python
# ❌ Hardcodear mapeo
def make_node(token):
    if token["type"] == "HEADING_ATX":
        return {"type": "heading", ...}
    elif token["type"] == "HR":
        return {"type": "hr", ...}
    # ... 20 elif más
```

**Problema**: agregar token nuevo requiere modificar función gigante.

**Solución**: tabla de mapeo + dispatch.

```python
# ✅ Mapeo configurable
NODE_BUILDERS = {
    "HEADING_ATX": make_heading,
    "HR": make_hr,
    "TEXT": make_text,
    # ...
}

def make_node(token):
    builder = NODE_BUILDERS.get(token["type"])
    if builder:
        return builder(token)
```

## Conclusión

El módulo `parser` es el **puente entre sintaxis (tokens) y semántica (AST)**. Los principios clave son:

1. **Agrupación**: transformar tokens planos en estructura jerárquica
2. **Estados y buffers**: manejar construcciones multi-línea
3. **Flush explícito**: cerrar bloques abiertos (BLANK_LINE, cambio tipo, EOF)
4. **Separación clara**: parser construye, validator valida
5. **MVP primero**: headings + párrafos, luego iterar

¡Recuerda!: el parser debe ser **robusto pero permisivo**. Construye lo que ve, valida después. No intentes ser parser + validator al mismo tiempo.
